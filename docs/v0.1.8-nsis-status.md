# v0.1.8 — Silent NSIS installer status

## What ships

`desktop/src-tauri/installer.nsi` is a custom Tauri NSIS template
(`bundle.windows.nsis.template = "installer.nsi"`). It replaces the
default Tauri/MUI2 wizard entirely with a `SilentInstall silent`
installer that:

- Installs to `$LOCALAPPDATA\Programs\VRAELIS\` as `currentUser` —
  no UAC prompt.
- Registers the `VRAELIS://` URL scheme under `HKCU\Software\Classes`.
- Writes the Add/Remove Programs entry under HKCU.
- Creates Start menu + Desktop shortcuts (with the AppUserModelId set
  via Tauri's `SetLnkAppUserModelId` macro so taskbar pinning works).
- Auto-launches `VRAELIS.exe` from `.onInstSuccess` via
  `nsis_tauri_utils::RunAsUser`. The Tauri splash window then takes
  over the post-install UX.
- Skips the auto-launch + shortcut churn when the Tauri updater
  invokes the installer with `/UPDATE` (the updater plugin restarts
  the app itself).

The uninstaller runs silently too (`SilentUnInstall silent`).

## Caveats

1. **WebView2 bootstrap UI.** When WebView2 isn't already installed,
   we no longer run Tauri's WebView2 bootstrapper (the default
   template does this in a dedicated section with a download progress
   line). On the vast majority of Windows 11 machines WebView2 is
   pre-installed, so this is a non-issue. If telemetry shows install
   failures on bare Windows 10 boxes, re-add the WebView2 section
   from `desktop/src-tauri/target/release/nsis/x64/installer.nsi`
   (the previously generated template) — it can be kept silent by
   passing `/silent` to the bootstrapper, which our config already does.

2. **Reinstall / downgrade prompts.** The default template shows a
   custom "uninstall existing version?" page when an older install is
   detected. We dropped it. Reinstalls overwrite in place. The
   updater plugin handles version comparisons before invoking us.

3. **SmartScreen warning.** Silent or not, Windows SmartScreen will
   still show its own "unrecognized app" dialog for unsigned
   installers. Code-signing the bundle is the only fix; that is out
   of scope for v0.1.8.

4. **NSIS still shows a tiny tray-corner "writing files" balloon on
   some Windows builds.** This comes from the OS, not NSIS, and only
   appears for a fraction of a second.

## Tauri Handlebars variables consumed

The template uses the standard Tauri-injected variables so that
`tauri build` populates them at bundle time:

- `{{manufacturer}}`, `{{product_name}}`, `{{version}}`,
  `{{version_with_build}}`
- `{{main_binary_name}}`, `{{main_binary_path}}`
- `{{bundle_id}}`, `{{copyright}}`, `{{out_file}}`, `{{arch}}`
- `{{installer_icon}}`, `{{estimated_size}}`

If a future Tauri release renames any of these, the build will fail
with an unresolved-template-variable error — fix by consulting the
generated `target/release/nsis/x64/installer.nsi` for current names.
