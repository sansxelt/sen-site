# Design 05 — Homepage storyboard

The complete homepage narrative. **Phase 0 implements sections 01, 02, 03 (as the flagship console), and 08**;
the rest are specified here for Phases 1–2. Every section states one idea, uses real (or clearly-labeled fixture)
data, and carries an explicit honesty boundary — the page practices the trust it sells.

Honesty rule for the whole page: everything describes what ships **today** or is explicitly marked as direction.
Living Guarantees, drift detection, automatic reverification, Proof Links, and published benchmarks are **Next /
Horizon**, never shown as shipping. No invented logos, revenue, users, accuracy, or catch-rate numbers.

---

## 01 — Hero  *(built)*
- **Purpose:** state the aspiration and ground it in what ships today, in one screen.
- **Copy:** "AI can build the company. Vraelis *proves it works*." / "Today, Vraelis independently verifies critical
  workflows in deployed web applications using reviewed proof plans, real browser execution, and evidence." CTAs:
  *Watch a real verification* (to the console) · *Verify a deployment*.
- **Composition:** centered editorial column, warm paper with a faint emerald radial; Instrument Serif flourish on
  "proves it works". A short honesty note under the CTAs.
- **Interaction / transition:** the flagship console begins immediately beneath and auto-plays.
- **Desktop / mobile:** headline clamps 2.5→4.6rem; CTAs inline → stacked.
- **Honesty boundary:** the note names the demonstration as anonymized fixture data.

## 02 — The trust gap  *(built)*
- **Purpose:** name the problem — the builder should not be the final authority on whether it works.
- **Copy:** section head "The system that built it should not be the final authority on whether it works." Two cards:
  *the coding agent reported* ("Subscription checkout and Pro access are complete and working.") vs *Vraelis observed*
  ("Payment succeeded, but Pro access did not persist. The claim did not hold."). Thesis: "One says it is done. The
  other *proves whether it is*."
- **Composition:** agent card recessed/muted; Vraelis card white with the observation in Failed red-brown.
- **Desktop / mobile:** two columns → stacked; thesis centered.
- **Honesty boundary:** the observation is the fixture record's real outcome, not a general claim.

## 03 — The real production story  *(built, as the flagship console)*
- **Purpose:** show a verification end-to-end and the Failed→Failed→Verified lineage as one continuous narrative.
- **Composition/interaction:** the proof console — claim → obligations (spine) → live execution → evidence → gapped
  ring conclusion, with three record tabs and a replay/step/scrub control set. Auto-plays; visitor can take over.
- **Real data:** anonymized fixtures modeled on the real production sequence (Pro-purchase persistence).
- **Honesty boundary:** "separate, preserved historical record; a later Verified never overwrites an earlier
  failure"; scoped "Verified on the checked workflow"; explicit fixture disclaimer in the footer.

## 04 — How Vraelis proves it  *(Phase 2)*
- **Purpose:** show the operating loop as one evolving workspace, not six equal feature cards.
- **Copy beats:** state what must be true → derive proof obligations → validate the plan → approve the exact plan →
  execute against the pinned deployment → inspect evidence → hand the failure back for repair → independently verify
  the new deployment.
- **Composition:** a single horizontal proof-path that advances through the eight beats; each beat swaps in the
  matching product surface. Reuses the node-rail motif.
- **Honesty boundary:** every beat maps to a real capability shipping today.

## 05 — Product surfaces  *(Phase 2)*
- **Purpose:** show what genuinely ships: web app, reviewed plans, verification records, evidence, repair handoff,
  API, CLI, webhooks, CI, integrations.
- **Composition:** restrained surface gallery (real component crops, hairline-framed), not a logo grid.
- **Honesty boundary:** only surfaces that exist today; API/CLI/webhooks/CI shown as real endpoints/commands.

## 06 — Today / Next / Horizon  *(Phase 2)*
- **Copy:** **Today** — verify a critical workflow in a deployed web application. **Next** — keep approved
  Guarantees proven across relevant releases. **Horizon** — prove the software operating an AI-built company keeps
  upholding what the business requires.
- **Composition:** three columns on one timeline, visibly de-emphasizing Next/Horizon (direction, not shipping).
- **Honesty boundary:** Next/Horizon are explicitly labeled direction; nothing there is presented as available.

## 07 — Trust & research  *(Phase 3)*
- **Purpose:** substantiate with real production evidence and methodology (determinism, scoped verdicts, the
  false-Verified emphasis).
- **Honesty boundary:** no invented customers, revenue, accuracy, or benchmark numbers; only real methodology and
  real production runs, clearly framed.

## 08 — Final CTA  *(built)*
- **Copy:** "Stop taking the agent's word for it." CTAs: *Verify a deployment* · *Watch the proof*. Footer carries
  the mark, the prototype label, and the fixture-data disclaimer.
- **Honesty boundary:** footer states plainly this is a prototype on anonymized fixture data, not a live customer
  deployment, with no private identifiers or evidence.
