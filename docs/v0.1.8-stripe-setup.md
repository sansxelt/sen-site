## 3. Webhook endpoint

Point Stripe at:

```
https://VRAELIS.ai/api/stripe/webhook
```

Events to enable on the endpoint (Developers → Webhooks → endpoint →
"Select events"):

- `payment_intent.succeeded`           — credits one-time boosts
- `customer.subscription.created`      — activates plan + sends welcome email
- `customer.subscription.updated`      — handles cancellation scheduling, plan swaps
- `customer.subscription.deleted`      — archives the plan, sends end-of-plan email
- `invoice.payment_succeeded`          — same handler as `invoice.paid`; renewal email
- `invoice.paid`                       — renewal success
- `invoice.payment_failed`             — dunning email
- `invoice.upcoming`                   — 7-day heads-up email

After saving, copy the **Signing secret** (`whsec_...`) into
`STRIPE_WEBHOOK_SECRET`.

For local dev, run:

```
stripe listen --forward-to http://localhost:3000/api/stripe/webhook
```

…and use the temporary `whsec_...` it prints.

## 4. SQL migration — `boost_credits`

Run the SQL in `docs/v0.1.8-boost-credits.sql` against production
Supabase (SQL Editor or your migration tool). One row per purchased
one-time boost; the `payment_intent.succeeded` handler in
`app/api/stripe/webhook/route.ts` writes them, and the gating layer in
`lib/plan-limits.ts` (`hasUnconsumedBoost`, `consumeBoost`,
`consumeBoostForKind`) burns them when a user hits their plan cap on
chat / image / voice / copilot.

Schema summary:

```
boost_credits (
  id                    uuid pk,
  email                 text,
  addon_key             text,                 -- e.g. 'session_boost'
  stripe_payment_intent text unique,          -- idempotency key
  created_at            timestamptz default now(),
  consumed              bool   default false,
  consumed_at           timestamptz
)
```

The `stripe_payment_intent` unique constraint is what makes the webhook
idempotent — Stripe redelivers events on transient failures, and the
unique violation gracefully no-ops on the second insert.

## 5. End-to-end test

1. Set test-mode keys + price IDs.
2. `stripe listen --forward-to http://localhost:3000/api/stripe/webhook`.
3. From the desktop billing panel, click **Buy Session Boost**.
4. Use Stripe test card `4242 4242 4242 4242`, any future expiry, any CVC.
5. Confirm:
   - Modal closes, billing panel refreshes (no error toast).
   - `boost_credits` table has a fresh row with `consumed=false`.
   - Hit the chat hard cap (or just call `/api/ai/chat` with a free
     account that's already past 50 chats); the next request should
     succeed and flip the row to `consumed=true`.
